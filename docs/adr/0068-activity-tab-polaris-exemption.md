# ADR-0068: アクティビティタブでは Polaris の規定を適用しない

- **Status**: Proposed
- **Date**: 2026-09-29

## Context

Polaris（ADR-0038 / `docs/design-system.md`）はアプリ全体に次を MUST として課す:

- アクセントは常に 1 色（ゴールド / アイスブルー）。多色を併用しない
- UI フィードバックは即時（0ms）。トゥイーン・フェードなどのアニメーションを使わない
- 色・寸法は `PolarisTokens` 経由。影・発光で面を分けない

アクティビティタブ（ADR-0067）は放送用レベルゲージと自動車のタコメータを模した
計器盤で、その価値は「緑 / 琥珀 / 赤の帯」「発光」「針のなめらかな動き」にある。
デザインモックで検討した結果、ユーザーは **この機能に限って Polaris の規定を無視し、
特に針の動きのなめらかさを優先する** と判断した。

## Decision

**アクティビティタブのメーター描画領域に限り、Polaris の単一アクセント・
アニメーション 0ms・発光禁止の各規定を適用しない。**

### D1. 適用除外の範囲

- 対象はアクティビティタブの **メーター描画領域**（LEVEL / TACHO の各
  `CustomPainter` とシフトライト）のみ。
- タブの外枠（タブストリップ・ツールバー・ディスプレイパネルのベゼル）と、
  アプリの他の画面は従来どおり Polaris に従う。ツールバーのトグル類も Polaris の
  コンポーネントを使う。

### D2. 許可するもの

- 多色の計器色: LED の緑 / 琥珀 / 赤、DIGITAL の VFD オレンジ、レッドゾーンの赤など
- 発光表現（点灯セグメント・針・数値のグロー）
- 連続アニメーション: ばね＋ダンパの針、PPM 風のバー減衰、ピークホールドの落下、
  TACHO 表示直後にフルスケールまで振って戻るオープニング演出、シフトライトの点滅
- 円形の文字盤など、R=4px・4px グリッドに乗らない形状

### D3. それでも守るもの

- 色はメーター専用の `ActivityMeterPalette`（`ThemeExtension`）に集約し、
  コンポーネントへ `Color(0x...)` を直書きしない。このパレットはアクティビティ
  タブ外から参照しない。
- OS のアニメーション低減設定が有効なら、補間・演出をやめて値を即時表示する。
- 文字盤は装飾を足さない。光だまり・艶・カーボン模様・アイボリー目盛り・針の影は
  モックで試して「安っぽい」「電車のメーターのよう」と却下したため採らない。

## Why

計器の読みやすさは色の帯と針の慣性に強く依存し、単一アクセントと 0ms では
「ひと目で負荷の勢いが分かる」という機能そのものが成り立たない。Polaris の
機能主義（見た目は機能から導く）に照らしても、この画面では多色と動きが機能である。
一方で除外をアプリ全体に広げると Polaris の一貫性が崩れるため、範囲を描画領域に
限定する。

## Trade-offs

- **アプリ内に 2 つの見た目のルールが併存する**: 範囲をこの ADR と
  `docs/design-system.md` に明記し、他画面への流用を禁じることで抑える。
- **将来の画面が前例として除外を求める可能性**: 除外は個別に ADR を要すること
  とし、本 ADR を一般的な例外規定にはしない。
