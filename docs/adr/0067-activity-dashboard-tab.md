# ADR-0067: アクティビティモニタをワークスペースタブとして追加する

- **Status**: Accepted
- **Date**: 2026-09-29（2026-10-06 実装結果を反映して Accepted）

> 仕様・設計の詳細は `openspec/changes/add-activity-dashboard-tab/` を参照。
> 見た目はデザインモック（`openspec/changes/add-activity-dashboard-tab/mock/meters.html`）で合意した。

## Context

トップバーのアクティビティモニタ（ADR-0039）は CPU / メモリのミニバーと上位
プロセス一覧だけを持つ常駐の簡易表示である。重い Skill やビルドを回しながら負荷の
推移を眺めたい場面では情報量も視認性も足りず、ユーザーは OS 標準のアクティビティ
モニタへ切り替えている。

ディスク / ネットワーク I/O は ADR-0048 でトップバーに足す形で提案・実装したが、
ネットワークの値を正しく取れず不採用にした（原因の記録は残っていない）。

## Decision

**ワークスペースのタブ種別 `WorkspaceTab.activity` を追加し、大型の「計器盤」と
して CPU / メモリ / I/O を表示する。トップバーのモニタはそのまま残す。**

### D1. 単一インスタンスのタブ

システム全体の値を映すだけなので、ワークスペースに 1 つだけ置く。開く操作で既存が
あればアクティブ化する。開き方は「+」メニュー・トップバーのポップオーバーの
「タブで開く」・コマンド `openActivityTab`（ADR-0033）の 3 経路。

### D2. 表示モードは LEVEL と TACHO（4 スタイル）

- **LEVEL**: 放送用レベルゲージ風の縦 LED バー（40 セグメント・緑 / 琥珀 / 赤・
  ピークホールド・PPM 風の減衰）
- **TACHO**: CLASSIC（針）/ DIGITAL（オレンジ蛍光表示管風のセグメント円弧）/
  RACE 1 / RACE 2（GR86 / BRZ 風クラスタ＋シフトライト）
  - RACE 2 は中央が Track Mode 風の右肩上がりバーグラフ
  - RACE 1 は同じクラスタの中央だけを通常モード風の丸型タコにしたもの
    （2026-10-06 追加。旧 RACE の保存値は RACE 2 として読む）

CPU / メモリの目盛りはタコメータらしく 0〜10（×10 %）。CPU は既定で全体 1 本、
「全コア表示」でコア別を追加する。選んだモード・スタイル・全コア表示は永続化する。

メーターの大きさはペインの大きさから決める。全メーターが収まる最大サイズを選び
（LEVEL はチャンネル幅を詰めてから折り返し、TACHO は大・小・コア別メーターの
一辺を縮める）、どうしても収まらない極端に小さいペインでだけスクロールさせる。

### D3. 表示項目

CPU（全体 / コア別）、メモリ、スワップ、ディスク I/O、ロードアベレージ（macOS
のみ）、ネットワーク I/O。ネットワークは実装の最初に取得方法を検証し
（`if_data` の 32bit ラップアラウンドが疑わしい。`if_data64` / `GetIfTable2` で
OS 標準モニタと突き合わせる）、正しく取れなければ外す。プロセス別 I/O は扱わない。

**ネットワークの検証結果: 採用**（macOS 26 / 2026-09-29。詳細は design.md D8）

- macOS ではサードパーティに渡る IF カウンタが `if_data` / `if_data64` のどちらでも
  32bit で一周しており（1 KiB 単位に丸め済み）、64bit 版を使っても回避できない。
  IF ごとに 2³² を法として差分を取ると `netstat -ib` 由来のレートと一致した。
- VPN 利用中は同じ通信がトンネル（`utun*`）と物理 IF の両方に載るため、
  合計には `en*` だけを使う。
- ネイティブは `en*` の IF ごとに累積値を返し、Dart 側で IF ごとに剰余差分を
  取ってから合計する。
- ADR-0048 で値が正しく取れなかったのは、合計値の差分（一周で負になる）と
  VPN の二重計上が原因だった可能性が高い。
- Windows（`GetIfTable2`）は実装済みだが、実機での突き合わせは未実施。

### D4. ネイティブは累積値のスナップショットを返し、差分は Dart で取る

既存 `getSystemMetrics` は CPU の前回 tick をネイティブ側に 1 つ持つため、タブと
トップバーが同じ経路を叩くと差分区間を奪い合って両方の値が歪む。新メソッド
`getSystemSnapshot` は状態を持たずに累積カウンタだけを返し、差分・レート計算は
呼び出し側の ViewModel が行う。既存メソッドは変更しない。

### D5. 表示中だけ 250ms でポーリングし、描画は毎フレーム補間する

タブが所属ペインのアクティブタブである間だけ 250ms 間隔で取得する（非アクティブ
タブも `IndexedStack` で mount されたままなので、mount ではなくアクティブ状態で
判定する）。描画側の Ticker がサンプル間をばね＋ダンパ（針）や PPM バリスティクス
（バー）で補間し、60fps でなめらかに動かす。トップバーの 1 秒ポーリングは据え置く。

### D6. 描画は `CustomPainter`、書体は同梱

外部パッケージは使わない。計器らしさの大半は書体に依るため、数値用に Barlow
Condensed、ラベル用に Chakra Petch（いずれも SIL OFL）を同梱する（ADR-0040 の
ライセンス登録に従う）。

### 実装状況（2026-10-06）

- macOS: 3 経路からの起動、全モード・全スタイル・全コア表示、負荷時のレッドゾーン /
  シフトライト / ピークホールド、非アクティブ時のポーリング停止、トップバー表示への
  非干渉を目視で確認した。
- Windows: 実装済み。実機での確認（スナップショットの値・ネットワークの突き合わせ・
  ロードアベレージが出ないこと）は未実施で、確認結果はこの ADR に追記する。

## Why

負荷の「今」だけでなく勢い（上がり方・張り付き具合）を、アプリを離れずに腰を
据えて見られるようにするため。数値の羅列ではなく、ひと目で読める計器の見た目を
優先した。見た目の方向性（放送機器・自動車の計器）はデザインモックでユーザーと
反復して決めた。

## Trade-offs

- **描画負荷が CPU メーター自体に乗る**: 毎フレームの再描画はタブ表示中のみ。
  `RepaintBoundary` の分割と発光の限定で抑えるが、観測者効果はゼロにはならない。
- **ネイティブ実装の拡張**: macOS（`host_processor_info` / IOKit / `vm.swapusage` /
  `getloadavg`）と Windows（`NtQuerySystemInformation` / PDH / `GetIfTable2`）で
  取得経路が増える。取れない項目はキーを返さずメーターを出さない設計で吸収する。
- **Polaris の規定から外れる**: 別途 ADR-0068 で範囲を限定して適用除外とする。
