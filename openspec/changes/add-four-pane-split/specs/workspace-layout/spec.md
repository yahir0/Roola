# workspace-layout

## MODIFIED Requirements

### Requirement: 4 ペインスロット構成

システムはコンテンツを持つペインスロットのみを描画対象とする SHALL。
ワークスペースは `topLeft` / `topRight`（上段）と `bottomLeft` / `bottomRight`（下段）の
4 つのペインスロットを持つ。各スロットはタブ群を保持し、タブを 1 つ以上持つスロットを
「コンテンツあり」、0 個のスロットを「空」とする。

#### Scenario: 4 スロットすべてにコンテンツがある

- **WHEN** `topLeft` / `topRight` / `bottomLeft` / `bottomRight` のすべてがタブを 1 つ以上持つ
- **THEN** 上段に `topLeft` と `topRight` を、下段に `bottomLeft` と `bottomRight` を
  それぞれ左右 2 分割で配置した 2×2 の 4 ペインレイアウトを描画する

#### Scenario: `bottomRight` が空のときは従来の 3 ペイン

- **WHEN** `topLeft` / `topRight` / `bottomLeft` にコンテンツがあり `bottomRight` が空である
- **THEN** 上段に `topLeft` と `topRight` を左右 2 分割で、下段に `bottomLeft` を
  **横いっぱい**に配置した 3 ペインレイアウトを描画する

#### Scenario: 空スロットは描画されない

- **WHEN** あるスロットのタブ数が 0 になった
- **THEN** そのスロットは描画対象から外れ、残りのスロットでレイアウトを再フローする

### Requirement: スロット崩し再フロー

システムはレイアウトを自動的に再フローする SHALL。
再フローは上段・下段それぞれのコンテンツを持つスロットに応じて決まり、片方の段に
コンテンツが無い場合はもう一方の段を画面全高に広げる。

#### Scenario: 下段が空になると上段のみ

- **WHEN** `bottomLeft` / `bottomRight` の両方のタブがすべて閉じられ、上段にコンテンツが残っている
- **THEN** 上段のスロットを画面全高に広げて描画する（上段に 2 つあれば左右 2 分割、
  1 つなら単一ペイン全画面）

#### Scenario: 上段が空になると下段のみ

- **WHEN** `topLeft` / `topRight` の両方が空になり、下段にコンテンツが残っている
- **THEN** 下段のスロットを画面全高に広げて描画する（下段に 2 つあれば左右 2 分割、
  1 つなら単一ペイン全画面）

#### Scenario: 各段に 1 つずつ残ると上下 2 分割

- **WHEN** 上段・下段にそれぞれコンテンツを持つスロットが 1 つずつになった
- **THEN** その 2 つを上下 2 分割で、それぞれ横いっぱいに描画する

#### Scenario: コンテンツが 1 スロットだけになると単一ペイン全画面

- **WHEN** コンテンツを持つスロットが 1 つだけになった
- **THEN** そのスロットを画面全体に単一ペインとして描画し、従来の単一ペイン表示と同じ
  見た目になる

#### Scenario: 空スロットへのタブ追加で再び分割される

- **WHEN** 空だったスロットに新しいタブが追加された
- **THEN** そのスロットを含めてレイアウトを再フローし、分割表示に戻す

### Requirement: スプリッタによるリサイズ

システムはユーザーのドラッグ操作でペインの大きさを変更できる SHALL。
レイアウトには上下分割・上段左右分割・下段左右分割の 3 本のスプリッタがあり、上段と
下段の左右分割位置は互いに独立して変化する。

#### Scenario: 上下スプリッタのドラッグ

- **WHEN** ユーザーが上下スプリッタを上下にドラッグする
- **THEN** 上段と下段の高さ比率が変化し、ドラッグ位置に追従する

#### Scenario: 上段左右スプリッタのドラッグ

- **WHEN** ユーザーが上段の左右スプリッタを左右にドラッグする
- **THEN** `topLeft` と `topRight` の幅比率が変化し、下段の分割位置は変化しない

#### Scenario: 下段左右スプリッタのドラッグ

- **WHEN** 4 分割状態でユーザーが下段の左右スプリッタを左右にドラッグする
- **THEN** `bottomLeft` と `bottomRight` の幅比率が変化し、上段の分割位置は変化しない

#### Scenario: スプリッタは単一ペイン時に表示されない

- **WHEN** レイアウトが単一ペイン全画面の状態である
- **THEN** スプリッタは表示されない

### Requirement: 起動時の既定 3 ペイン

起動時、システムは既定の 3 ペインレイアウトを生成する SHALL。`bottomRight` は空とし、
4 分割は起動直後には現れない。

#### Scenario: 起動直後のレイアウト

- **WHEN** アプリを起動する
- **THEN** `topLeft` にエクスプローラタブ（$HOME）、`topRight` にエクスプローラタブ（$HOME）、
  `bottomLeft` に素のシェルのターミナルタブ（$HOME）を持ち、`bottomRight` が空の
  3 ペインレイアウトを表示する

## ADDED Requirements

### Requirement: 右下ペインへのタブ移動による 4 分割

ユーザーは明示的な操作によってのみ 4 分割に到達できる SHALL。システムはタブの
右クリックメニューに「タブを右下ペインへ移動」を提供し、右下ペインが描画されている間は
ドラッグ＆ドロップでのタブ移動も受け付ける。

#### Scenario: 右クリックメニューから 4 分割にする

- **WHEN** 3 分割状態でいずれかのタブを右クリックし「タブを右下ペインへ移動」を選ぶ
- **THEN** そのタブが `bottomRight` へ移動し、下段が左右 2 分割された 4 分割レイアウトになる

#### Scenario: 現在のペインへの移動項目は出ない

- **WHEN** `bottomRight` のタブを右クリックする
- **THEN** 「タブを右下ペインへ移動」は表示されず、他の 3 ペインへの移動項目が表示される

#### Scenario: 右下ペインへ DnD で移動する

- **WHEN** 4 分割状態で他ペインのタブを右下ペインのタブストリップへドラッグ＆ドロップする
- **THEN** そのタブが `bottomRight` のドロップ位置へ移動し、per-tab 状態
  （エクスプローラの履歴・ターミナルの表示内容）は失われない

#### Scenario: 右下ペインを空にすると 3 分割へ戻る

- **WHEN** `bottomRight` のタブをすべて閉じる、または他ペインへ移動する
- **THEN** `bottomRight` は描画対象から外れ、下段は `bottomLeft` が横いっぱいの
  3 分割レイアウトに戻る

### Requirement: 右下ペインの振る舞いの同一性

`bottomRight` は他のペインスロットと同一の振る舞いを持つ SHALL。ただし、システムが
自動的にタブを開く先としては選ばれない。

#### Scenario: 右下ペインでのタブ操作

- **WHEN** `bottomRight` が描画されている
- **THEN** タブストリップの「+」からのタブ追加、× での閉じる、タブの並べ替え、
  キーボードショートカットによるタブ切替が他ペインと同様に動作する

#### Scenario: 自動起動は常に左下ペインへ

- **WHEN** `bottomRight` にフォーカスがある状態で、タイル右クリックの「ターミナルで開く」/
  「Claude Code で開く」、worktree 作成後の起動、Git ビューの「ターミナルを開く」、
  ノートパッドボタン、サイドバーからの起動のいずれかを実行する
- **THEN** 新しいタブは `bottomLeft` に開かれ、`bottomRight` の作業中セッションは
  押し流されない

#### Scenario: フォーカス中ペインへの新規タブ

- **WHEN** `bottomRight` のタブにフォーカスがある状態で「新しいエクスプローラタブ」/
  「新しいターミナルタブ」コマンドを実行する
- **THEN** 新しいタブは `bottomRight` に追加される
